Building RESTful APIs in Go: Design Patterns and Best Practices

#golang #rest-api #backend #design-patterns

After building REST APIs in Go for the past three years, I've learned that the standard library gives you everything you need - but knowing how to structure your code makes all the difference. Let me share the patterns that have worked best for me.

Project Structure That Scales

Here's the structure I use for all my Go APIs:

myapi/
├── cmd/
│   └── api/
│       └── main.go
├── internal/
│   ├── handlers/
│   ├── models/
│   ├── repository/
│   └── middleware/
├── pkg/
│   └── response/
└── go.mod

The internal directory is key - Go won't let other projects import from it, which helps maintain clean boundaries.

Handler Pattern

I structure my handlers as methods on a struct that holds dependencies:

type Handler struct {
    db     *sql.DB
    logger *log.Logger
    cache  Cache
}

func NewHandler(db *sql.DB, logger *log.Logger, cache Cache) *Handler {
    return &Handler{
        db:     db,
        logger: logger,
        cache:  cache,
    }
}

func (h *Handler) GetUser(w http.ResponseWriter, r *http.Request) {
    userID := chi.URLParam(r, "id")
    
    user, err := h.repository.GetUser(r.Context(), userID)
    if err != nil {
        h.respondError(w, http.StatusNotFound, "user not found")
        return
    }
    
    h.respondJSON(w, http.StatusOK, user)
}

Middleware for Cross-Cutting Concerns

Middleware is perfect for logging, authentication, and rate limiting:

func (h *Handler) LoggingMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        
        next.ServeHTTP(w, r)
        
        h.logger.Printf(
            "%s %s %s",
            r.Method,
            r.RequestURI,
            time.Since(start),
        )
    })
}

func (h *Handler) AuthMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        token := r.Header.Get("Authorization")
        
        if token == "" {
            http.Error(w, "unauthorized", http.StatusUnauthorized)
            return
        }
        
        userID, err := h.validateToken(token)
        if err != nil {
            http.Error(w, "invalid token", http.StatusUnauthorized)
            return
        }
        
        ctx := context.WithValue(r.Context(), "userID", userID)
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

Request Validation

Always validate input. I use a simple validation package:

type CreateUserRequest struct {
    Name  string `json:"name" validate:"required,min=2,max=100"`
    Email string `json:"email" validate:"required,email"`
    Age   int    `json:"age" validate:"required,min=18,max=120"`
}

func (h *Handler) CreateUser(w http.ResponseWriter, r *http.Request) {
    var req CreateUserRequest
    
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
        h.respondError(w, http.StatusBadRequest, "invalid request body")
        return
    }
    
    if err := h.validator.Struct(req); err != nil {
        h.respondError(w, http.StatusBadRequest, err.Error())
        return
    }
    
    // Process request...
}

Error Handling

Consistent error responses are crucial. Here's my approach:

type ErrorResponse struct {
    Error   string `json:"error"`
    Message string `json:"message"`
    Code    int    `json:"code"`
}

func (h *Handler) respondError(w http.ResponseWriter, code int, message string) {
    h.respondJSON(w, code, ErrorResponse{
        Error:   http.StatusText(code),
        Message: message,
        Code:    code,
    })
}

func (h *Handler) respondJSON(w http.ResponseWriter, code int, payload interface{}) {
    response, err := json.Marshal(payload)
    if err != nil {
        w.WriteHeader(http.StatusInternalServerError)
        w.Write([]byte("internal server error"))
        return
    }
    
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(code)
    w.Write(response)
}

Router Setup

I use chi router for its simplicity and middleware support:

func (h *Handler) Routes() http.Handler {
    r := chi.NewRouter()
    
    // Global middleware
    r.Use(middleware.Logger)
    r.Use(middleware.Recoverer)
    r.Use(middleware.Timeout(60 * time.Second))
    
    // Public routes
    r.Post("/api/v1/auth/login", h.Login)
    r.Post("/api/v1/auth/register", h.Register)
    
    // Protected routes
    r.Group(func(r chi.Router) {
        r.Use(h.AuthMiddleware)
        
        r.Get("/api/v1/users/{id}", h.GetUser)
        r.Put("/api/v1/users/{id}", h.UpdateUser)
        r.Delete("/api/v1/users/{id}", h.DeleteUser)
        
        r.Get("/api/v1/posts", h.ListPosts)
        r.Post("/api/v1/posts", h.CreatePost)
    })
    
    return r
}

Testing

Always test your handlers. Here's a simple example:

func TestGetUser(t *testing.T) {
    handler := NewHandler(mockDB, mockLogger, mockCache)
    
    req := httptest.NewRequest("GET", "/api/v1/users/123", nil)
    w := httptest.NewRecorder()
    
    handler.GetUser(w, req)
    
    if w.Code != http.StatusOK {
        t.Errorf("expected status 200, got %d", w.Code)
    }
}

Key Takeaways

  • Use dependency injection for testability
  • Middleware for cross-cutting concerns
  • Always validate input
  • Consistent error responses
  • Context for request-scoped values
  • Proper project structure from day one

These patterns have served me well across multiple production APIs. Start with these basics, and adjust based on your specific needs.
