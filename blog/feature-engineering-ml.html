Feature Engineering Techniques for Machine Learning

#data-science #machine-learning #python #feature-engineering

Feature engineering is often the difference between a mediocre model and one that actually works in production. I learned this the hard way when my first ML model had 60% accuracy, and after proper feature engineering, it jumped to 89%. Let me share what I've learned.

Why Feature Engineering Matters More Than You Think

Here's the truth: fancy algorithms won't save you if your features are garbage. I've seen teams spend weeks tuning hyperparameters when they should have spent that time understanding their data and creating better features.

A good feature should:

  • Have a clear relationship with the target variable
  • Be available at prediction time
  • Not leak information from the future
  • Be interpretable (bonus points)

Handling Missing Values (The Right Way)

Don't just fill everything with zeros or means. Think about WHY the data is missing:

import pandas as pd
import numpy as np

# Create a missing indicator
df['age_missing'] = df['age'].isnull().astype(int)

# Fill with median for numerical
df['age'].fillna(df['age'].median(), inplace=True)

# For categorical, 'Unknown' might be informative
df['category'].fillna('Unknown', inplace=True)

# Sometimes the missingness itself is a feature
df['num_missing_features'] = df.isnull().sum(axis=1)

In one project, the fact that income was missing turned out to be a strong predictor - people who didn't report income were more likely to default on loans.

Target Encoding (My Favorite)

This technique has saved me countless times with high-cardinality features:

def target_encode(df, column, target, smoothing=10):
    # Calculate global mean
    global_mean = df[target].mean()
    
    # Calculate category means and counts
    agg = df.groupby(column)[target].agg(['mean', 'count'])
    
    # Smooth the means
    smoothed = (agg['mean'] * agg['count'] + global_mean * smoothing) / (agg['count'] + smoothing)
    
    # Map back to dataframe
    return df[column].map(smoothed)

# Usage
df['city_encoded'] = target_encode(df, 'city', 'target')

The smoothing parameter prevents overfitting on rare categories. I usually set it to 10-20 depending on dataset size.

Creating Interaction Features

Sometimes the magic happens when you combine features:

# Simple interactions
df['price_per_sqft'] = df['price'] / df['square_feet']
df['income_to_debt_ratio'] = df['income'] / (df['debt'] + 1)  # +1 to avoid division by zero

# Polynomial features (use carefully!)
from sklearn.preprocessing import PolynomialFeatures

poly = PolynomialFeatures(degree=2, include_bias=False)
poly_features = poly.fit_transform(df[['age', 'income']])

# This creates: age, income, age², age*income, income²

Pro tip: Don't go crazy with polynomial features. I once created degree-3 polynomials on 20 features and ended up with 1,540 features. The model was slower than a snail and didn't perform better.

Time-Based Features

If you have timestamps, extract everything you can:

df['date'] = pd.to_datetime(df['date'])

# Basic extractions
df['year'] = df['date'].dt.year
df['month'] = df['date'].dt.month
df['day'] = df['date'].dt.day
df['dayofweek'] = df['date'].dt.dayofweek
df['hour'] = df['date'].dt.hour

# Cyclical encoding (important!)
df['month_sin'] = np.sin(2 * np.pi * df['month'] / 12)
df['month_cos'] = np.cos(2 * np.pi * df['month'] / 12)

# Time since event
df['days_since_signup'] = (df['current_date'] - df['signup_date']).dt.days

# Is it weekend?
df['is_weekend'] = df['dayofweek'].isin([5, 6]).astype(int)

The cyclical encoding is crucial - it tells the model that December (12) and January (1) are actually close together.

Aggregation Features

These are gold for user-level predictions:

# User behavior aggregations
user_features = df.groupby('user_id').agg({
    'purchase_amount': ['mean', 'sum', 'std', 'count'],
    'days_since_last_purchase': 'min',
    'product_category': lambda x: x.nunique()  # number of unique categories
})

# Flatten column names
user_features.columns = ['_'.join(col).strip() for col in user_features.columns]

# Time-based aggregations
df['purchases_last_30_days'] = df.groupby('user_id')['purchase_amount'].rolling(window=30).sum()

Text Features

Don't just use TF-IDF for everything:

# Basic text features
df['text_length'] = df['text'].str.len()
df['word_count'] = df['text'].str.split().str.len()
df['avg_word_length'] = df['text_length'] / df['word_count']
df['num_uppercase'] = df['text'].str.count(r'[A-Z]')
df['num_special_chars'] = df['text'].str.count(r'[!@#$%^&*()]')

# Sentiment (if relevant)
from textblob import TextBlob
df['sentiment'] = df['text'].apply(lambda x: TextBlob(x).sentiment.polarity)

Feature Scaling

Different algorithms need different scaling:

from sklearn.preprocessing import StandardScaler, MinMaxScaler, RobustScaler

# StandardScaler: for normally distributed features
# Good for: Linear models, Neural Networks
scaler = StandardScaler()
df[['age', 'income']] = scaler.fit_transform(df[['age', 'income']])

# MinMaxScaler: scales to [0, 1]
# Good for: Neural Networks, algorithms sensitive to feature magnitude
scaler = MinMaxScaler()

# RobustScaler: uses median and IQR, robust to outliers
# Good for: when you have outliers you can't remove
scaler = RobustScaler()

Tree-based models (Random Forest, XGBoost) don't need scaling, which is one reason I love them.

My Feature Engineering Checklist

  • ✓ Handle missing values thoughtfully
  • ✓ Encode categorical variables appropriately
  • ✓ Create domain-specific features
  • ✓ Generate interaction features
  • ✓ Extract time-based features
  • ✓ Create aggregation features
  • ✓ Scale features if needed
  • ✓ Remove redundant features
  • ✓ Validate features don't leak information

Common Mistakes to Avoid

1. Data Leakage: Using information that wouldn't be available at prediction time. I once included "days_until_churn" in a churn prediction model. Oops.

2. Not Using Cross-Validation: Always validate your features with proper CV to avoid overfitting.

3. Ignoring Domain Knowledge: Talk to domain experts. They know which features actually matter.

Final Thoughts

Feature engineering is more art than science. It requires creativity, domain knowledge, and lots of experimentation. Don't be afraid to try weird combinations - some of my best features came from random ideas.

Start simple, measure everything, and iterate. And remember: a simple model with great features beats a complex model with mediocre features every time.

Happy feature engineering! 🔬
