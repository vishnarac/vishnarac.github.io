CI/CD Pipeline with GitHub Actions and AWS

#devops #ci-cd #github-actions #aws

Manual deployments are error-prone and slow. I learned this after deploying the wrong branch to production at 2 AM. GitHub Actions changed everything - now every commit is tested, built, and deployed automatically. Let me show you how.

Basic CI Pipeline

Start with a simple workflow that runs tests on every push:

# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v3
    
    - name: Set up Go
      uses: actions/setup-go@v4
      with:
        go-version: '1.21'
    
    - name: Run tests
      run: |
        go test -v -race -coverprofile=coverage.out ./...
        go tool cover -html=coverage.out -o coverage.html
    
    - name: Upload coverage
      uses: codecov/codecov-action@v3
      with:
        files: ./coverage.out

Building and Pushing Docker Images

  build:
    needs: test
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v3
    
    - name: Configure AWS credentials
      uses: aws-actions/configure-aws-credentials@v2
      with:
        aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
        aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        aws-region: us-east-1
    
    - name: Login to Amazon ECR
      id: login-ecr
      uses: aws-actions/amazon-ecr-login@v1
    
    - name: Build and push image
      env:
        ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
        ECR_REPOSITORY: myapp
        IMAGE_TAG: ${{ github.sha }}
      run: |
        docker build -t $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG .
        docker push $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG
        docker tag $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG $ECR_REGISTRY/$ECR_REPOSITORY:latest
        docker push $ECR_REGISTRY/$ECR_REPOSITORY:latest

Deploying to ECS

  deploy:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'
    
    steps:
    - name: Configure AWS credentials
      uses: aws-actions/configure-aws-credentials@v2
      with:
        aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
        aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        aws-region: us-east-1
    
    - name: Download task definition
      run: |
        aws ecs describe-task-definition \
          --task-definition myapp \
          --query taskDefinition > task-definition.json
    
    - name: Update task definition
      id: task-def
      uses: aws-actions/amazon-ecs-render-task-definition@v1
      with:
        task-definition: task-definition.json
        container-name: myapp
        image: ${{ secrets.ECR_REGISTRY }}/myapp:${{ github.sha }}
    
    - name: Deploy to ECS
      uses: aws-actions/amazon-ecs-deploy-task-definition@v1
      with:
        task-definition: ${{ steps.task-def.outputs.task-definition }}
        service: myapp-service
        cluster: production
        wait-for-service-stability: true

Secrets Management

Never hardcode secrets. Use GitHub Secrets:

# In your workflow
env:
  DATABASE_URL: ${{ secrets.DATABASE_URL }}
  API_KEY: ${{ secrets.API_KEY }}

# Or use AWS Secrets Manager
- name: Get secrets
  run: |
    SECRET=$(aws secretsmanager get-secret-value \
      --secret-id prod/myapp/config \
      --query SecretString \
      --output text)
    echo "::add-mask::$SECRET"
    echo "SECRET=$SECRET" >> $GITHUB_ENV

Rollback Strategy

Always have a rollback plan:

  rollback:
    runs-on: ubuntu-latest
    if: failure()
    
    steps:
    - name: Rollback to previous version
      run: |
        PREVIOUS_TAG=$(aws ecr describe-images \
          --repository-name myapp \
          --query 'sort_by(imageDetails,& imagePushedAt)[-2].imageTags[0]' \
          --output text)
        
        aws ecs update-service \
          --cluster production \
          --service myapp-service \
          --force-new-deployment \
          --task-definition myapp:$PREVIOUS_TAG

Monitoring Deployments

Send notifications to Slack:

    - name: Notify Slack
      if: always()
      uses: 8398a7/action-slack@v3
      with:
        status: ${{ job.status }}
        text: 'Deployment to production: ${{ job.status }}'
        webhook_url: ${{ secrets.SLACK_WEBHOOK }}

Best Practices

  • Run tests before building images
  • Use caching to speed up builds
  • Tag images with git SHA for traceability
  • Implement health checks before marking deployment successful
  • Always have a rollback strategy
  • Monitor deployments and set up alerts

The Deployment That Saved Us

Last month, a bug made it to production. Our CI/CD pipeline detected the health check failures and automatically rolled back within 2 minutes. Users barely noticed. That's the power of automation.
